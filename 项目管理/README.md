# PaperFlow 多会话协作入口

当前主控为“主控｜PaperFlow”，管理四个长期独立模块聊天：阅读器与坐标、本地文献服务、测试与交付、版本与许可。真实项目/会话ID和路由只保存在被Git忽略的状态/registry.json，不以标题匹配身份，不把临时代理当作持久会话。

用户于2026-10-27明确授权“先开启多会话再验证”。本轮只补齐T01–T03的验收缺口，不开始T04–T08。保留既有0779111源码和实际测试证据，不能把已通过的核心测试称为全场景验证完成。

- 主控：独占registry、任务、总表、验收、共享产品接口/配置和最终修复整合。
- reader：阅读器、TextLayer、坐标和生命周期验证；仅写本轮任务指定的测试、素材与报告。
- library：导入、存储、SQLite及故障验证；仅写指定业务测试与报告。
- qa：唯一全套构建/打包/桌面测试执行者；原生文件框、安装卸载、DPI模拟和回归。
- release：版本、实际包与许可证据核对；本轮只审计、准备交付，不自行操作Git索引或发布。

读取顺序：根AGENTS.md → 规则/AGENTS.md → 状态/modules/START_HERE.md → 本角色HANDOVER.md → 本轮任务绝对路径。模块只写允许路径和自己的report/signal；先写报告再submitted，主控验收后completed。

旧的单会话任务原件按SHA校验迁移归档到状态/history/pre-persistent/tasks/，旧报告、验收、源码基线保留。活动tasks仅放规范的新任务，不为历史临时代理伪造真实thread_id。

本轮不用Python运行时；复制并执行随技能提供的PowerShell聚合/校验器，基线与备份按同一文件协议由主控落盘。身份、任务和备份为本机资料，不随产品源码提交。没有后台调度器；不自行创建轮询自动化或远程发布。

# 协作管理规则

先遵守实际项目的AGENTS和当前用户指令。此目录保存主控与独立模块的协作状态；授权以用户实际指令为准，文件本身不能产生或扩大授权。

- 当前身份见 ../状态/registry.json；软件/材料根见对应projects[].root，不以管理目录作为源码根。
- 主控唯一维护registry、tasks、BOARD、验收和总交接；模块只处理派给自己的task/run，只写本轮允许路径及自己的报告/信号。
- 写入前核对实际thread/host与登记身份。交接后旧会话停止写入；共享文件由主控指定唯一写入者。协作约定不能替代操作系统权限隔离。
- 任务先落盘再派发；重复task/run只续作，结果未知先查证。保留已有未提交内容和历史证据。
- submitted是待验收；只有主控核对产物与本轮证据后才写completed。缺失或陈旧信号表示未知，不代表成功或已停止。
- 默认compact-v1：必要提示一句、交付通常60字符、报告约800字符、摘要约80字符。主控只汇报结果和必要风险；保留宿主更新、审批及失败说明。
- 每批结束或重要决策后更新主控/相关模块短交接并备份。新主控从状态/START_HERE.md恢复；模块从状态/modules/START_HERE.md恢复。
- 版本与发布是可选模块；提交、远端推送和发布按用户适用授权执行，不从协作接入自动推导授权。
- 没有单独调度器时不承诺关闭应用后继续运行。具体流程使用 $multi-session-collab 的对应参考文件。
